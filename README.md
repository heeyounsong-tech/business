# PUNCH LAB

한국어 모바일 우선 10초 펀치 아케이드. 카메라 영상은 기기에서 처리하며 업로드·녹화하지 않습니다. 실측 속도 단위가 아닌 0~100 게임 지수를 표시합니다.

## 지금 확인한 상태

- 카메라 연결·오류 처리·10초 게임·결과·재도전·브라우저 최고 기록·친구 도전 링크 구현.
- 공식 MediaPipe Pose npm 배포본에 포함된 Lite 모델·WASM을 로컬 설치함. 외부 Google 모델 서버 허용이나 별도 API 키 없이 실행 가능.
- 실제 MediaPipe 모델 초기화 및 WASM 추론을 Chromium의 가상 카메라 프레임으로 실행해 통과함. 이 검사는 사람의 펀치 인식 정확도 검증과 다름.
- iPhone Safari·Android Chrome의 물리 기기 검증은 아직 수행하지 않음. [MOBILE-TEST.md](MOBILE-TEST.md) 참고.
- 기존 저장소에는 README만 있었으므로 새로 구현한 앱임.

## 설치·실행

Node.js 20.19+ 또는 22.12+, npm 필요. 검증 버전은 Node.js 24.19.0.

```bash
npm ci
npm run setup:assets
npm run dev
```

`setup:assets`는 고정 버전 `@mediapipe/pose@0.5.1675469404`의 공식 런타임·내장 모델을 `public/pose-runtime/`에 복사합니다. npm 잠금 파일의 무결성 검증을 유지합니다. Lite 모델만 사용하며 Full/Heavy 모델은 복사하지 않습니다. 다운로드할 별도 모델 서버가 필요하지 않습니다. `public/wasm/`에는 Tasks Vision 런타임도 복사합니다.

MediaPipe Pose Landmarker를 먼저 검토했으나 공식 `.task` 다운로드 서버가 현재 클라우드에서 차단되어, 공식 Pose Solutions 패키지의 내장 모델을 대체 엔진으로 추가했습니다. 로컬 `.task` 모델이 있으면 기존 Pose Landmarker를 시도하고, 준비 실패 시 내장 Pose Lite로 전환합니다. 다운로드한 단일 HTML은 공식 Pose npm CDN 파일을 사용합니다. 이 버전은 유지보수가 종료된 이전 API 계열이므로 향후 Tasks 모델을 안정적으로 설치할 수 있을 때 교체를 검토해야 합니다.

- 브라우저 테스트는 시스템 Chromium 또는 `CHROMIUM_PATH`를 사용합니다. 없으면 `npx playwright install chromium`이 필요합니다.

## HTTPS 배포

휴대폰에서는 HTTPS 주소를 Safari/Chrome으로 직접 열어야 합니다. HTTP LAN 주소·채팅 미리보기·파일 미리보기의 카메라 동작은 보장하지 않습니다. iframe 삽입 시 부모 Permissions-Policy와 `allow="camera"`가 필요합니다.

Vercel/Netlify/Cloudflare Pages의 빌드 명령:

```bash
npm ci && npm run setup:assets && npm run build:deploy
```

출력은 `dist`. `.wasm`은 `application/wasm`, 모델·data 파일은 바이너리로 제공하세요. API 키·로그인·DB는 필요하지 않습니다. 실제 공개 사이트의 설정 완료 여부와 배포 상태는 별도로 확인해야 합니다.

GitHub Pages는 `.github/workflows/pages.yml`이 main 반영 시 자동 배포를 시도하며 수동 실행도 가능합니다. 저장소 정책이 허용하면 Pages 활성화도 시도합니다. 저장소 하위 경로 빌드:

```bash
PUNCH_BASE_PATH=/business/ npm run build:deploy
```

루트/사용자 도메인은 기본 `/` 사용. 저장소 Pages 서비스 활성화는 GitHub 권한이 필요합니다. 워크플로 파일 또는 `gh-pages` 브랜치 존재만으로 사이트가 게시됐다고 판단하면 안 됩니다.

## 게임 흐름과 오류 처리

메인 → 카메라 허용 → 관절 프리뷰 → 가드 1.2초 → 3초 준비 → 10초 챌린지 → 결과. 카메라 없는 체험은 버튼/Space로 가상 입력하며 최고 기록·공유에서 제외합니다.

카메라와 AI 상태는 분리합니다. AI 준비가 실패해도 영상은 유지하고 점수 측정만 차단합니다. AI만 재시도할 때 기존 카메라 트랙을 유지합니다. 권한 대기 중 취소한 요청의 늦은 스트림은 해제하며 요청을 직렬화합니다. 일반 영상 조건으로 한 번 재시도하고, 재생 지연·영상 정지·장치 종료·권한 오류를 안내합니다. 백그라운드·화면 회전은 라운드를 취소하고 재준비합니다.

화면 아래 **카메라 연결 점검**에서 HTTPS·API·삽입 정책·카메라 트랙·AI 상태를 확인/복사할 수 있습니다. 영상은 포함하지 않습니다.

## 판정·점수와 한계

`src/engine.js`의 `CONFIG`에서 판정 상수를 관리합니다. 좌우 각각 가드 → 뻗기 → 1회 판정 → 가드 복귀 후 재허용입니다. 어깨·팔꿈치·손목 visibility 0.65 미만 또는 프레임 공백 220ms 초과는 해당 동작을 폐기합니다. 영상 비율을 반영하고 어깨 기준 손목 변위를 영상 속 팔 길이 평균으로 정규화합니다.

가드의 어깨-손목 거리는 팔 길이 평균의 1.8배 미만. 변위 0.15 이후 시간을 재며, 변위 0.65 이상·팔꿈치 약 141° 이상·동작 70~850ms일 때 판정합니다. 가드 복귀와 180ms 쿨다운이 다음 동작을 허용합니다.

```
D = 가드 대비 어깨 기준 정규화 손목 변위
velocityPart = min((D / 동작시간초) / 8, 1)
timePart = max(0, 1 - 동작시간ms / 850)
펀치 점수 = round(100 × 동작 중 최소 visibility × (0.7 × velocityPart + 0.3 × timePart))
스피드 지수 = 유효 펀치 점수 평균의 반올림
```

스피드 지수·최고 펀치 점수·유효 횟수·좌우 횟수·연속 성공을 표시합니다. 연속은 1.8초 안의 성공이며 추적 손실 시 끊깁니다. 0회는 측정 불가로 표시합니다. 등급은 80/60/40점 경계의 게임 요소입니다. 공유 링크는 `?target=0..100`이며 서버 검증이 없어 조작 가능하고 공인 랭킹이 아닙니다.

**물리적인 속도, 격투 능력, 운동 능력을 측정하지 않습니다.** 정면 깊이 이동·주먹 쥠·원근·몸 회전·카메라 흔들림·양팔 가림을 완벽히 구별하지 못합니다. 팔을 펴는 비펀치 동작도 통과할 수 있으며, 빠른 펀치는 추론 사이에 누락될 수 있습니다. 누락을 임의 점수로 보충하지 않습니다. 60°/90° 촬영은 실험 조건이며 각도를 자동 검증하거나 보정하지 않습니다. 90°에서 반대팔이 가려지면 사선으로 조정하세요. 같은 동작의 점수 일관성, 실물 기기 성능·발열·인식 정확도는 추가 검증이 필요합니다.
